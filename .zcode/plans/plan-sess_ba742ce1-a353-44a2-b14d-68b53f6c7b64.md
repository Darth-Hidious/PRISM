## F1 (HIGH, ship-blocker) — the fail-closed channel DEADLOCKS instead of denying

**Verified:** `research_driver.rs:258` is `let (_tx, rx) = tokio::sync::mpsc::channel::<ApprovalResponse>(1);`. `_tx` is a **named binding** (underscore-prefix ≠ the bare `_` pattern), so the sender lives until the end of the `Box::pin(async move { ... })` block — i.e. **across `run_turn().await`** at line 269. tokio `Receiver::recv()` returns `None` only when *all* senders are dropped; with a live sender + empty buffer it **pend forever**. So the first non-auto-approved tool reaching `agent_loop.rs:1173` (`rx.recv().await`) hangs `run_turn` → the campaign iteration never completes → `prism research --local` freezes with no error, no checkpoint, no budget check. My comment ("sender is dropped immediately") is false.

**Fix:**
1. `research_driver.rs:258`: change to `let (tx, rx) = tokio::sync::mpsc::channel::<ApprovalResponse>(1); drop(tx);` — an explicit drop before the turn so `recv()` observes `None` → the gate's `Some(Deny) | None` arm (`agent_loop.rs:1188`) fires → the tool is cleanly denied → the model gets a "denied" tool-result (already captured into `notes` by my emit closure) → the turn continues honestly.

Rewrite the comment to state the real mechanism: "the sender is dropped before the turn so `recv()` returns `None` → deny. **Must be an explicit `drop(tx)`** — `let (_tx, rx)` or `let _ = tx` would hold the sender alive across `run_turn().await` and deadlock the gate."
