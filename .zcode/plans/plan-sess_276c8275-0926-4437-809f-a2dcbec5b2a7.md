## PATCH 1 (Part B) — Agent/human parity: 4 new agent tools

Land this first — it's the most isolated and lowest-risk, and it has zero TUI coupling.

**File: `crates/agent/src/command_tools.rs`**

Add four `CommandToolSpec` entries to `COMMAND_TOOLS` (near the existing `agent`/`run` `RootArgs` roots at line 433-450). Kinds chosen from the CLI shapes verified in `crates/cli/src/main.rs`:

1. **`pyiron`** — `kind: RootSubcommand { subcommands: &["status", "install", "update"] }`, `root: "pyiron"`, `aliases: &[]`, `permission_mode: PermissionMode::FullAccess`, `requires_approval: true` (mirrors `agent`/`run`: install/update mutate the pyiron env). Description steers the model: "Run `prism pyiron ...` for the local pyiron integration (status/install/update). Prefer this over `execute_bash` for pyiron lifecycle."
2. **`federation`** — `kind: RootSubcommand { subcommands: &["whoami", "peers"] }`, `root: "federation"`, `aliases: &[]`, `permission_mode: PermissionMode::ReadOnly`, `requires_approval: false` (both subcommands are read-only per `FederationCommands` enum at `main.rs:902-920`). Net-new and distinct from the existing `query_federated` tool (which is `root: "query"`, node-gated, dashboard-API based).
3. **`report`** — `kind: RootArgs`, `root: "report"`, `aliases: &[]`, `permission_mode: PermissionMode::WorkspaceWrite`, `requires_approval: true` (it writes a log file and may push to GitHub per `handle_report`). `RootArgs` lets the model pass `args: ["<description>", "--log-file", "<path>", "--no-github"]` directly — matches `report`'s flat CLI shape (positional + flags, no subcommand).
4. **`configure`** — `kind: RootArgs`, `root: "configure"`, `aliases: &["config"]`, `permission_mode: PermissionMode::FullAccess`, `requires_approval: true` (mutates live config: provider/url/model/embedding-model). `RootArgs` matches its flag-only CLI shape.

**Why `RootArgs`/`RootSubcommand` and not new `CommandToolKind` variants:** these two kinds need zero new code — `schema_for_spec` (line 1719) and `build_execution` (line 2164) already dispatch on them generically. The model gets a strong typed schema (`subcommand` enum for pyiron/federation; `args: array<string>` for report/configure), and execution lands in the same `execute_cli_command` subprocess path the other roots use. Per-turn top-K + `find_tools` discovery is untouched — these are discoverable, don't bloat the 15-tool budget, and `is_command_tool` / `meta_tools::is_reserved_tool_name` pick them up automatically.

**Deliberately NOT added** (per task): `setup`/`login`/`backend`/`use` — auth + config-hot-swap, intentionally human-only.

## PATCH 2 (Part A) — Persistent human shell mode

Front-end only. Reuses the existing `/bash` path — **no new execution primitive, no new network path**. When shell mode is ON, each submitted line is rewritten to `/bash <line>` so it lands in the existing `send_command` arm of `App::send_message` (`app.rs:3138`), which the backend already routes through `parse_bash_slash_action` → `execute_manual_tool_call` → `execute_bash` with its explicit-intent bypass + `permissions.decision_for` + policy gates intact.

**User answered: "Keybind + `!`-prefix both."** So three entry points:

1. **Persistent toggle** — global `Ctrl-B` keybind (mirrors `Ctrl-Y` copy mode at `app.rs:765-770`) + `/shell` slash command (mirrors `/copy` at `app.rs:3110-3113`) + palette entry `shell.toggle` (mirrors `copy.toggle` at `command.rs:529-536` + `app.rs:3057`).
2. **One-shot `!`-prefix** — a leading `!` on a submitted line runs that single line as `/bash <rest>` even when shell mode is OFF (ephemeral, no mode change). Think shell-escape.

### Changes in `crates/tui/src/app.rs`

- **`App` struct** (~line 441, next to `copy_mode: bool`): add `pub shell_mode: bool`. Initialize `shell_mode: false` in `App::new` (~line 546, next to `copy_mode: false`).
- **`toggle_shell_mode(&mut self)`** helper (~line 2938, modeled on `toggle_copy_mode`): flips the flag, emits a toast (`"shell mode ON — each line runs as /bash, Ctrl-B to exit"` / `"...OFF"`), and sets `self.focus = Focus::Input` on enable so the user can type immediately.
- **`handle_key` global arm** (~line 770, after the `Ctrl-Y` block): add `Ctrl-B` → `self.toggle_shell_mode(); return;`.
- **`send_message` routing** (`app.rs:3138`): the single load-bearing change. Before the existing `if trimmed.starts_with('/')` branch, add:
  ```rust
  // Shell mode: route bare lines through the existing /bash path
  // (explicit-intent: bypasses the approval prompt, still enforces
  // permissions.decision_for + the policy engine + plan-mode gates
  // inside execute_manual_tool_call). A leading `!` is a one-shot
  // shell escape even when the persistent mode is off.
  let is_bang_escape = trimmed.starts_with('!');
  if self.shell_mode || is_bang_escape {
      let cmd = if is_bang_escape { &trimmed[1..] } else { trimmed };
      let cmd = cmd.trim();
      if cmd.is_empty() {
          return;  // empty `!` or empty line in shell mode → no-op
      }
      let forwarded = format!("/bash {cmd}");
      self.push_user(trimmed);  // show what the user typed (with `!` if present)
      let _ = self.backend.send_command(&forwarded);
      self.is_waiting = true;
      self.is_thinking = true;
      self.status_text = "Running…".to_string();
      self.auto_scroll = true;
      self.reset_stream_metrics();
      return;
  }
  ```
  Note: client-side slash commands (`/help`, `/cost`, `/goal`, etc. at `app.rs:3092-3128`) still fire **first** because they're matched before this block — so `/shell` and the existing client commands keep working even in shell mode. The shell-mode rewrite only catches bare (non-`/`) text.
- **`/shell` client command**: add `"/shell" => { self.toggle_shell_mode(); return; }` to the client-side `match trimmed` block (~line 3114, next to `/copy`).
- **`dispatch_command`**: add `"shell.toggle" => self.toggle_shell_mode(),` arm (~line 3057, next to `copy.toggle`) so the palette entry resolves.

## PATCH 3 (Part C) — Route `/campaign start` to native `goal_start`

**File: `crates/agent/src/protocol.rs`**

Add `handle_campaign_slash_command(args, slash_ctx) -> Result<bool>`, mirroring `handle_node_slash_command` (line 3830) — which already builds a `CommandToolRuntime` from `slash_ctx` (3839-3845):

```rust
async fn handle_campaign_slash_command(
    args: &[String],
    slash_ctx: &SlashCommandContext,
) -> Result<bool> {
    if args.first().map(String::as_str) != Some("campaign") {
        return Ok(false);
    }
    // Only `start` gets the native goal_start path — it's the long-lived
    // verb that otherwise hits the spawn_prism_cli 30s-timeout stub.
    // status/list/resume keep falling through to spawn_prism_cli.
    if args.get(1).map(String::as_str) != Some("start") {
        return Ok(false);
    }

    // Parse /campaign start --goal X [--elements Y] [--objective Z]
    // [--max-iterations N] [--batch-size N] [--budget X] [--approval-gates N]
    // into the goal_start tool's JSON arg shape (mirrors GoalStart's
    // build_execution at command_tools.rs:2605, but in reverse).
    let mut goal: Option<String> = None;
    let mut elements: Vec<String> = Vec::new();
    // ... simple flag parser over &args[2..] filling the typed fields ...
    let goal = goal.ok_or_else(|| anyhow::anyhow!(
        "/campaign start requires --goal <text>"))?;

    let args_json = serde_json::json!({
        "goal": goal,
        "elements": elements,           // empty array is fine
        // ...optional objective/max_iterations/batch_size/budget_usd/approval_gates...
    });

    let runtime = CommandToolRuntime {
        current_exe: slash_ctx.current_exe.clone(),
        project_root: slash_ctx.project_root.clone(),
        python_bin: slash_ctx.python_bin.clone(),
        ..Default::default()
    };
    let result = crate::command_tools::execute_command_tool(
        &runtime, "goal_start", &args_json, None,
    ).await?;

    // Emit the result through the normal ui channels so the TUI sees the
    // goal id + the tool card, exactly as if the agent had called goal_start.
    emit_notification("ui.text.delta", serde_json::json!({
        "text": result.get("stdout").and_then(|v| v.as_str())
            .unwrap_or("Campaign started.")
    }));
    emit_notification("ui.turn.complete", serde_json::json!({}));
    Ok(true)
}
```
